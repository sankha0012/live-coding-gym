Batching bugs live at the boundaries, so I test both an uneven length, where the last batch is short, and an exact multiple, where a naive loop adds an empty batch at the end. I also test a batch size larger than the list and the empty list. The failure path is an invalid size: I check both zero and a negative number with pytest.raises, because a guard written only for zero lets negatives through and returns nothing silently. Last, I check the input is untouched.
