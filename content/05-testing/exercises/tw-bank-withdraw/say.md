I test the normal result first, then the boundaries. Withdrawing exactly the balance must work and give 0, because a bug that uses >= instead of > rejects it. Zero and a negative amount are two separate tests, since a check for only zero or only negative looks fine on one of them. The overdraft is the important failure path: I use pytest.raises(RuntimeError), which fails if the function returns a balance instead of raising. That last point matters in a payments system, where a silent failure is worse than a loud one.
