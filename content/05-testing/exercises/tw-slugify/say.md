I test one behaviour per test so a failure names the bug. First the main promise: capitals become lowercase and words are joined with one dash. Then the edges where implementations usually break: repeated spaces, spaces at the start and end, tabs and newlines, and the empty or blank string. A good test file fails on the version that forgets to lowercase, on the one that only replaces single spaces, and on the one that returns a dash for empty input. Five small tests are enough, because each one covers a different way the code can go wrong.
