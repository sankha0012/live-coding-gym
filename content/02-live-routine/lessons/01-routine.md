# The routine


<p class="lede">This is what interviewers score. Say each step out loud; it turns slow syntax into a visible method.</p>
<ol class="routine">
<li><span><b>Clarify (2–3 min).</b> Restate the task. Ask about definitions and edge cases: “Does revenue include the fee? Do cancelled orders count? What about nulls?”</span></li>
<li><span><b>Tiny example (1 min).</b> “With 3 orders like this, the answer should be…”</span></li>
<li><span><b>Plan as comments (2 min).</b> <code># 1. filter delivered  # 2. join  # 3. group</code></span></li>
<li><span><b>Code in small runnable steps.</b> Run every line or two; print <code>.head()</code> and <code>.shape</code>.</span></li>
<li><span><b>Test.</b> The tiny example plus one edge case: empty input, nulls, ties.</span></li>
<li><span><b>Improve and interpret.</b> Complexity, trade-offs, and what the number means for the business.</span></li>
</ol>
<div class="say">“I don't remember the exact method name; the idea is to group by city and sum. I'll write it like this and check.”</div>
<p>Stuck on logic: go back to the tiny example and do it by hand. After about 3 minutes of silence, ask for a hint. Taking a hint well is scored.</p>
