This code scores a list of rows in batches and returns the scores in the same order as the rows. The helper chunks takes any iterable, makes one iterator, and uses islice to pull size items at a time until nothing is left. That means it also works for a generator, and an empty input yields no batches. Time is O(n), and memory is one batch plus the scores list, so the input does not need to be a list. The model is called n divided by batch_size times, which is where batching saves time compared with one call per row. I added a length check because a model that silently returns fewer scores would shift every score onto the wrong row. The main risk is partial failure: if the model raises on batch 40, everything scored so far is thrown away, and a retry starts over and pays for it again. In production I would catch errors per batch, retry with backoff, and either checkpoint results or return them with the failed batches marked.
