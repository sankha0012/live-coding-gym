This function calls fn and retries it when it raises TransientError. Before each retry it waits a random time between zero and an exponentially growing delay, capped at a maximum, which is called full jitter and stops many clients from retrying together. On the last attempt it re-raises, so the caller still learns about the failure. Sleep and the random generator are parameters, so tests run instantly and the same way every time. The cost is at most attempts calls and a bounded total wait. The main risk is idempotency: if fn charges a card and the first call really succeeded before a timeout, the retry repeats the effect. I would retry only idempotent calls or send an idempotency key, and add a total time budget.
