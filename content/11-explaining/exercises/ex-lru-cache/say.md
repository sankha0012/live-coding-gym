This is a least recently used cache built on OrderedDict, which remembers the order of keys. Every get or put moves the key to the end, so the front is always the least recently used key, and put drops the front item when the size passes the capacity. Get, put and eviction are O(1), and memory is O(capacity). The cached decorator stores function results by the argument tuple. The risk is that it uses None to mean a miss, so a function that legitimately returns None is never cached and runs every time, as the demo shows for lookup of zero. I would use a private sentinel object instead. Arguments must also be hashable and there is no lock, and in production functools.lru_cache already solves this.
