This is a token bucket rate limiter. It lets a caller make about rate requests per second, and it allows a burst of up to capacity requests after a quiet period. When allow is called it reads the clock, adds elapsed time times rate to the tokens, caps the total at capacity, and then spends cost tokens if there are enough. Each call is O(1) in time and memory, because it does not keep a list of past requests. I use max of zero and elapsed so a clock that goes backwards cannot remove tokens. The main risk is concurrency. Two threads can both read the same token count and both be allowed, so real use needs a lock or an atomic store, and across several servers the state must live in something shared like Redis. A second edge case is a cost larger than capacity: it will be refused forever, which should be a clear error.
