I cover the three outcomes first: a value inside the range stays, a value below becomes lo, a value above becomes hi. Testing both sides matters, because a version that only handles one bound still passes half the cases. Then the edge where lo equals hi, which must work and not raise. Finally the failure path with pytest.raises: inverted bounds must raise ValueError, not be silently swapped. I add one test with negatives and floats so the code does not rely on positive ints.
