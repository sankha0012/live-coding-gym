Add an optional fifth parameter `max_items=None`: `process_until(items, handler, deadline, clock, max_items=None)`. When it is a number, at most that many items are started, even if the deadline has not passed; the items not started go into `remaining`, in their original order. For example `process_until([1, 2, 3, 4], f, 100, clock, max_items=2)` calls `f` for 1 and 2 only, and returns `([f(1), f(2)], [3, 4])`. `max_items=0` runs nothing. With `None`, only the deadline limits the work, as before. The deadline rule stays: it can still stop the job earlier than `max_items`.
