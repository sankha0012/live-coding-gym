I describe each key as a small parser plus a default, then loop over them, so adding a key is one line. Absent keys get the default, but a present bad value is a problem and never silently replaced, because a typo in production should fail loudly at start-up. I collect every problem and raise one ConfigError, so the operator fixes everything in one go instead of one error per restart. Booleans are parsed from the text on purpose, since bool("false") is True. The cost is linear in the number of keys. One trade-off: an empty string is invalid, not "use the default", which is stricter but unambiguous.
