I use one sorted call with a tuple key: first a flag that pushes None scores to the end, then the negative score so higher comes first, then the id to break ties. Python's sort is stable, so records that are fully equal keep their input order, and the output is the same on every run. It is O(n log n) and it returns a new list, so the caller's data is untouched. I avoid reverse=True here because it would also reverse the id order, and I never compare None with a number, which raises TypeError.
