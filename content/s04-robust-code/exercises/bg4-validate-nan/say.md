The bug is that NaN is not treated as missing. The check only looks for `None`, but a NaN converts to a float without error, and comparisons with NaN are always false, so it also passes the range check. The result is a clean row that still contains NaN and an empty issues list. The fix is to treat `None` and NaN the same way, using `math.isnan` for floats, and to use the default and record `missing:<field>`. I would keep a test with a NaN, because NaN is the value that makes every other check look fine.
