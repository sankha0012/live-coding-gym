I start with the happy path: each unit alone, then combinations such as 1h30m, because a wrong multiplier shows up there. I check that the result is an int, since the spec says whole seconds. Most of the value is in the failure path. I test the empty string, text with no digits, a number with no unit, junk after valid parts, wrong order and repeated units. A lenient parser that ignores junk would pass every happy-path test, so only the invalid-input tests catch it. I use parametrize so each bad input is its own case.
