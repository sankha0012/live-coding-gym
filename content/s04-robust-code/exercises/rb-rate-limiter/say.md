I keep a token count and a last-seen time, and I refill lazily when allow is called, so there is no background thread. The refill is elapsed times rate, capped at capacity so an idle client cannot save up a huge burst. A denied call removes nothing, and a clock that goes backwards adds nothing. Each call is O(1) time and memory. The clock is injected so the tests can move time exactly, with no sleeping. The trade-off is that this is per process: with many servers I would need a shared store such as Redis, and a lock if threads share the bucket.
