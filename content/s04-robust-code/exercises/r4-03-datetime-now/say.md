Line by line. events holds four fixed naive datetimes: 20 February 2024 at 08:00, and 1, 3 and 4 March 2024. last_week_events reads datetime.now() itself and keeps events from the last 7 days before that moment. Run today, that window is far after March 2024, so no event is in it and the first line is "with datetime.now(): 0". last_week_events_at takes now as an argument. With now = 5 March 2024 12:00 the window starts on 27 February 12:00, which excludes 20 February and includes the 1, 3 and 4 March events: 3. Calling it again with the same now gives 3 again.

Answers. The two functions have the same logic, but the first one gives a different answer depending on the day it runs: it printed 3 on 5 March 2024 and prints 0 today (and would print 0 for any run more than a week after the last event). In production a hidden clock read means a job cannot be re-run to reproduce yesterday's numbers (a backfill silently uses today's window), a test that passes today fails next week, and two steps of the same pipeline that each call now() can disagree about "today", especially around midnight. Passing now as a parameter makes the function pure: tests give it a fixed value, a backfill gives it the historical date, and the job's entry point reads the clock once and hands the same value to every step.

Trap: a hidden dependency on the wall clock. Defence: inject the time (a now argument or a clock object), read it once at the top of the job, and log it.
