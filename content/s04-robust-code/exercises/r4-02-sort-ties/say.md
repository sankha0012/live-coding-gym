Answers. The naive result differs because the sort only decides the order of unequal scores; for ties it simply preserves whatever order the data arrived in. In production that arrival order often comes from a database without ORDER BY, a thread pool, a set, or a file listing, so the same model scores produce a different top-N on every run: flaky tests, flip-flopping recommendations, A/B groups that do not match, and an unexplainable "the ranking changed" incident. The key (-r[1], r[0]) negates the score so that ascending order means highest score first, and uses the name as an explicit, total tie-breaker, so the final order depends only on the data values and never on arrival.
