The bug is that the refill uses the raw time difference, which can be negative when the clock goes backwards. Then the bucket loses tokens instead of gaining them, and it can go negative, so valid requests are rejected until the clock catches up. The fix is to clamp the elapsed time with `max(0.0, now - self.last)` and still update `self.last` to the new, lower time, so later refills are measured from there. A limiter should never punish callers for a clock change it did not cause.
