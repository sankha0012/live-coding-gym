There are eight real labels and eight predicted probabilities. y_pred turns each probability into 1 when it is at least 0.5, giving [1, 0, 0, 1, 1, 0, 1, 0]. Comparing with y_true: positions 0, 3 and 6 are true positives (3), position 4 is a false positive (1), position 2 is a false negative (1), and the rest are true negatives (3). Precision is tp / (tp + fp) = 3/4 = 0.75, recall is tp / (tp + fn) = 3/4 = 0.75. roc_auc_score with probabilities measures how often a random positive is scored above a random negative, and gives 0.875. The last line passes the hard 0/1 predictions instead.

Answers. The counts are 3, 1 and 1, giving 0.75 for both precision and recall. The last two prints differ (0.875 and 0.75) because AUC needs the ranking information in the scores; with y_pred there are only two distinct values, so the curve collapses to a single threshold and the result equals the average of recall and specificity, here (0.75 + 0.75) / 2. The right call uses y_prob. The 0.5 threshold decides y_pred, so precision and recall depend on it; AUC computed from y_prob does not.

The trap. The code runs without error when you pass y_pred to roc_auc_score, and the number looks plausible, so the mistake is easy to miss. Check which argument an assistant passes to AUC.
