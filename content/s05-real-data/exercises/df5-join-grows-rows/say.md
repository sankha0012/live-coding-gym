More rows after a left join is a warning, not extra data. A left join should keep exactly one row per order. If the count grows, then the key is not unique in the restaurants table, and some orders matched two or more restaurant rows. Those orders are now duplicated, so any sum of order value, any order count and any average per restaurant is inflated, and the same order can appear twice in training with different restaurant attributes. I would not quietly drop the duplicate restaurants, because that picks one of two conflicting records at random and hides a data problem that someone should fix at the source. Instead I compare the row count before and after the merge and raise an error if it changed, or I pass `validate="many_to_one"` to the merge so pandas raises. Then I look at which ids are duplicated and why. One caveat: a duplicate key that no order uses does not change the count, so it is not an error for this pipeline, but I would still log it.
