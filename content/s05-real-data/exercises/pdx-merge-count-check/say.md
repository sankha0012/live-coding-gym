I use a left merge so no order can be dropped, and then I compare the row count with the original. If the restaurants table has a duplicate key, each order of that restaurant is repeated, the count grows, and every later sum would be inflated without any error. So I raise a ValueError with both counts instead of returning wrong data. The check costs nothing. Pandas also has the validate argument, merge with validate many_to_one, which does a similar check, but the explicit count is easy to read and to explain.
