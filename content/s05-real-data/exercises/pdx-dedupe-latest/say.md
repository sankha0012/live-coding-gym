I sort by the time column with a stable sort, so equal times keep their input order. Then drop_duplicates on the key with keep last leaves the newest row per key, and the later row wins a tie. I sort by key and reset the index so the output is deterministic. It is O(n log n) because of the sort. Calling drop_duplicates without sorting first is the classic bug, because it keeps the last row in the file, which is not always the latest in time.
