The bug is an overlapping boundary. Train uses `<=` the cutoff and test uses `>=` the cutoff, so any order at exactly the cutoff timestamp lands in both. The spec says train is strictly before and test is at or after, so every row is in exactly one side. The fix is to compute one boolean mask, `ts < cutoff`, and use it for train and its negation for test. Using the negation makes overlap and loss impossible by construction. This matters for ML because a row in both sets leaks training data into the evaluation. The tell was two separately written conditions for the two sides.
