The model prompt fixes the function signature, the model interface and the exact output file, including a status column so no row is lost. It states the failure policy: retry, split in halves, mark the row failed, never abort. It also asks for streaming, order preservation and handling of a wrong-length result, which are the real production risks. It asks for tests with a fake failing model and for an explanation of memory, so I can defend the design. A weak prompt such as "score this big file with my model" would load everything into memory and crash on the first bad batch.
