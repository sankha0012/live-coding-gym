Add an optional third parameter `reserve=0`: the number of tokens to keep free for the model's reply. Messages must then fit in `budget - reserve` instead of `budget` (the system message is still always kept, and the rule of stopping at the first message that does not fit is unchanged). With the default, behaviour is unchanged. Example: with the usual four messages, `trim_history(msgs, 11)` keeps the system message, the assistant reply and the refund message (2 + 5 + 4 = 11 words), but `trim_history(msgs, 11, reserve=2)` has only 9 available, so the assistant message no longer fits and the result is the system message and the refund message.
