The model prompt names the real risk, leakage, and forces the split to be by customer, not by row. It asks for a hash of a stable key with hashlib and explicitly bans random without a seed and the built-in hash(), which is the usual hidden source of non-determinism. It also states ordering, validation and the empty case, and asks for tests that check the no-overlap property. A weak prompt such as "split data 80/20" would give a row-level random shuffle that leaks customers and changes every night.
