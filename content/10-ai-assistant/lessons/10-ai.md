# Prompting while they watch


<p class="lede">At iFood you may use your own AI assistant, and the interviewer grades your prompts. A good prompt is a spec: it shows you understood the problem before the AI wrote anything.</p>
<h3>The five-part prompt</h3>
<ol class="routine">
<li><span><b>Context.</b> What the code is for and the shape of the inputs and outputs.</span></li>
<li><span><b>Exact behaviour.</b> The signature and a rule for every edge case: missing, NaN, empty, ties, errors.</span></li>
<li><span><b>Constraints.</b> Python 3.11, standard library only (or which libraries), deterministic, don't mutate inputs, keep it short.</span></li>
<li><span><b>Tests.</b> "Then write asserts for: …" listing the cases you care about.</span></li>
<li><span><b>Scope.</b> One function at a time. Never "build the whole thing".</span></li>
</ol>
<h3>Weak vs strong</h3>
<pre class="code wrap">Weak:   write a function to clean the input data for the model

Strong: Write validate(row, schema) in Python 3.11, standard library only. schema maps field -> (type, min, max, default).
        Missing/None/NaN -> default and record "missing:&lt;field&gt;"; unconvertible -> default and "bad_type:&lt;field&gt;";
        out of range -> clip and "clipped:&lt;field&gt;". Don't modify the input. Return (clean_row, sorted(issues)).
        Then write 3 asserts: a clean row, a row with every problem, and a NaN.</pre>
<h3>After the answer comes back</h3>
<ol class="routine">
<li><span><b>Read it aloud before pasting.</b> Say what each block does.</span></li>
<li><span><b>Run the tests.</b> Add one edge case the AI didn't think of.</span></li>
<li><span><b>When it's wrong, say why and re-prompt with the failing case</b> ("this fails when the prediction is 0.0 because of 'if not pred'; fix only that"). Catching an AI bug is the best signal you can give.</span></li>
<li><span><b>Simplify.</b> Delete anything you can't explain. You'll be asked to explain every line.</span></li>
</ol>
<p>Every "Robust ML systems" drill has an example prompt. Write yours first, then compare.</p>
