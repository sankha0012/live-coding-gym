The model prompt names the function signature, the schema format and the exact output, so the assistant cannot guess. It lists the edge cases that break feature validation in production: NaN, None, bool passing as int, inclusive bounds and unknown features. It asks for determinism and for no exceptions on bad input, which is the robustness the interviewer cares about. It asks for tests and for an explanation, so I stay in control and can explain the result. A weak prompt such as "write a validator for features" would miss the schema format, the error report, NaN and the failure path.
