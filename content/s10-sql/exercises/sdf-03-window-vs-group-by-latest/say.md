GROUP BY collapses each customer to one row, and MAX(created_at) gives me the latest date, but not the order_id, subtotal or status of that order. Those columns are not in the group, so I would have to join the result back to orders on customer_id and created_at to get the full row. That join is where it breaks. If a customer has two orders with the same timestamp, both match and the customer appears twice, so the table is no longer one row per customer. A window function avoids this: ROW_NUMBER numbers the rows inside each customer, newest first, and I keep number 1, so I get the whole row and exactly one per customer. I add order_id DESC after created_at as a tie-break, so the result is deterministic and the same on every run. The cost is that I cannot filter on a window function in the same SELECT, so I wrap it in a subquery or a CTE, and each partition is sorted, so it is O(n log n). If I only needed the latest date, or a count or a sum per customer, GROUP BY would be simpler and the right tool.
