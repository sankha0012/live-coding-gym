I group by the business key and keep the groups with more than one row using HAVING COUNT(*) > 1, because WHERE runs before the grouping. The order_id check is trivial since it is a primary key, so the business key is the real test. It is one scan plus a group, so O(n) with a hash group. The trade-off is that two orders by the same customer at the same restaurant on one day can be real, so these rows are suspects to review, not rows to delete.
