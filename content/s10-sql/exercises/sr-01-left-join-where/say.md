This query is meant to count delivered orders per customer, and it reads in this order. FROM customers with LEFT JOIN orders pairs each customer with their orders and keeps customers that have none, filling the order columns with NULL. WHERE o.status = 'delivered' then keeps only rows whose order status is delivered. GROUP BY c.name makes one group per customer, COUNT(o.id) counts the non-NULL order ids in each group, and ORDER BY sorts by name.

For this data it returns two rows: Ana with 1 and Bruno with 1. Ana has two orders but only one is delivered, so she counts 1. Carla's only order is cancelled and Davi has no orders at all, so both disappear from the result.

The trap is the WHERE clause. After the LEFT JOIN, Davi's row has o.status equal to NULL, and NULL = 'delivered' is not true, so WHERE drops it. Carla's joined row has status 'cancelled', which is also dropped. A filter on the right-hand table in WHERE therefore turns the LEFT JOIN into an inner join. The intended query moves the condition into the join: LEFT JOIN orders o ON o.customer_id = c.id AND o.status = 'delivered'. I ran that version too, and it returns all four customers: Ana 1, Bruno 1, Carla 0, Davi 0.
