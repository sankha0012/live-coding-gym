The most likely cause is that promotions has more than one row per customer_id, because then each order matches every promotion of that customer and is repeated, so its subtotal is summed several times. SQL raises no error, since a one-to-many join is valid. First I check the row counts: I count the orders before the join and after it, and if the count after is larger, the join multiplied rows. Then I look at the right-hand table directly, with `SELECT customer_id, COUNT(*) FROM promotions GROUP BY customer_id HAVING COUNT(*) > 1`, which lists the keys that cause it. I can also compare `COUNT(*)` with `COUNT(DISTINCT o.order_id)` after the join. To prevent it, I first reduce promotions to one row per customer, for example with a subquery that keeps the latest or the one valid promotion, and join to that, or I aggregate it before joining. I would not just wrap the sum in DISTINCT, because that removes real orders that have the same subtotal. Finally, I write the row count check as an assertion or a test, so it fails loudly if the data changes.
