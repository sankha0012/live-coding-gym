retry is a function that takes the number of attempts and returns a decorator. The decorator takes a function and returns wrapper, which is a closure that remembers times and func. Writing @retry(3) above fetch means fetch = retry(3)(fetch), so the name fetch now points at wrapper. The calls dict counts how many times the real function actually runs. The first call to fetch() goes into wrapper, which loops over attempt 1 to 3. On attempt 1 the real function raises ConnectionError, so the wrapper prints "attempt 1 failed: timeout" and loops again. Attempt 2 fails the same way. On attempt 3 the counter reaches 3, the real function returns "ok", and wrapper returns that immediately. The program prints ok. The last line prints the function's name, fetch, and the counter, 3.

Q1: It replaces fetch with the wrapper function that adds the retry behaviour, at the moment the def statement runs.
Q2: The first two calls to the real function raise ConnectionError, which the wrapper catches and prints, and the third call succeeds and returns "ok".
Q3: The loop would end without returning and the wrapper would raise RuntimeError saying fetch gave up after 3 tries; functools.wraps copies the original name and docstring onto wrapper, which is why fetch.__name__ prints fetch instead of wrapper.
