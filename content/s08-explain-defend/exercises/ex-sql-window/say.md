This query looks at delivered orders only. For each customer it numbers the orders from newest to oldest with ROW_NUMBER and, in the same pass, sums the customer's totals with SUM OVER the partition. The filter rn = 1 keeps the latest order, which carries the lifetime total, and we keep the top five by that total. The window runs in a CTE because SQL does not allow window functions in WHERE. The cost is a sort inside each partition, about O(n log n). The risk is determinism: two orders with the same created_at make ROW_NUMBER pick one arbitrarily, so I would add order_id as a tie breaker. Also a NULL subtotal makes total NULL and SUM skips it, so I would use COALESCE if the business rule says so.
