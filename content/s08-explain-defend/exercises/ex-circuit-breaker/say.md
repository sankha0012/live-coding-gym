This is a circuit breaker around a dependency. It counts failures, and when they reach the maximum it records the time and opens, so later calls raise CircuitOpen at once without touching the dependency. After the reset time it lets one call through as a trial: success clears the state, and failure opens the circuit again. Each call costs constant time and memory, and the injected clock lets tests move time without sleeping. The main risk is concurrency. The state has no lock, so in a threaded service several calls can pass as trials at the same moment and the counters can race. It also counts every Exception, so a bug in our own code can open the circuit. I would add a lock, allow one trial, and count only errors that mean the dependency is unhealthy.
