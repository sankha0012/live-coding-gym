I count the orders once, then add up the counts of each breakdown and subtract. By status I group the table directly. By restaurant I use an inner join, so any order with an unknown restaurant would drop out and show up as a positive difference. It is O(n) per check. A zero difference does not prove the data is right, but a non-zero one always means a join or a filter is losing or duplicating rows.
By courier the difference is not 0: cancelled orders have no courier, so the inner join drops them. That is expected here, so I read a non-zero difference against the data rules before calling it a bug.
