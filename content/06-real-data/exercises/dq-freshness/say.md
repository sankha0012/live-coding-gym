I take the latest created_at per restaurant with MAX and compare it with a fixed cutoff in HAVING. I start from the restaurants table with a LEFT JOIN, so a restaurant that never sent an order is reported instead of silently missing. The timestamps are in YYYY-MM-DD HH:MM:SS, so string comparison matches time order. A fixed reference time keeps the check reproducible; in production I would pass the run time in as a parameter, not call the clock inside the query.
