A Pipeline chains the preprocessing steps and the model into one object. When I call fit, every step learns only from the training data, and when I call predict, the same steps run in the same order. In a loose script it is easy to fit a scaler on the full dataset before the split, which leaks test information into training, or to forget one step when serving. With a Pipeline inside cross-validation, the imputer and scaler are refitted on each training fold, so the scores are honest. I can also save one object with joblib and load it in production, so training and serving cannot drift apart. A Pipeline does not fix bad data or weak features, and it does not track experiments or deploy anything.
