"A feature store is a shared system where features are defined once, computed, stored and served. It usually has an offline store for building training sets and an online store for fast lookups at prediction time. It solves training-serving skew, where the training code and the live code compute the same feature differently, and it stops teams from rebuilding the same feature many times. It can also build training data point-in-time correct, so a row only sees values known at that moment. An example is the number of orders a customer made in the last 30 days: computed once and used by both the training job and the live API. You do not need one with a single model, a small team or batch-only scoring, where a tested feature function and a table are enough, because a feature store adds real operating cost."
