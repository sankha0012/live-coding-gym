I walk the events once. A set of seen ids drops duplicates, and a dict keeps the best event per entity, replaced only when the new timestamp is not older. That makes the result depend on event time and not on arrival order, and the tie rule is explicit and deterministic. Time is O(n), memory is O(ids plus entities). The trade-off is that the seen set grows without bound in a real stream, so in production I would expire old ids or use a store with a TTL.
