The key identifies the request, not the payload, so a retry with the same key gets the same outcome and the side effect happens once. I store the outcome, result or exception, in a dict before returning, and I test membership with `in` because a result can legitimately be None. Storing the failure too means a retry does not repeat a charge that already half ran. The cost is O(1) per call and memory that grows with the number of keys. The trade-off is that a transient failure is also remembered, so in real systems I would store only permanent failures, or expire entries, and keep the store in a database shared between workers.
