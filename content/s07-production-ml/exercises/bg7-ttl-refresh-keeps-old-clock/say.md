The bug is in the branch of `set` that handles an existing key. It keeps the old timestamp, so setting a key again changes the value but not the expiry. The spec says a set restarts the TTL, and the same oldest-set-time ordering is used for eviction, so a refreshed key also looks older than it is and can be evicted too early. The fix is to delete the old entry and insert the key again with the value and `self.clock()`. That also moves it to the end of the dict, which keeps the oldest-first order correct. Replacing a key still must not evict another key, so I remove it before the size check. I confirmed it with a test: set at time 0, set again at time 5, and read at time 12 with a TTL of 10.
