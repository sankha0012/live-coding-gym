"I monitor three layers. First, service health: latency, error rate and throughput, as for any API. Second, data: missing values, out-of-range values and drift, which means comparing the live distribution of each important feature with the training one, for example with PSI or a statistical test. Third, model quality: the prediction distribution right away, and real metrics such as precision or error once the true labels arrive. This matters because a model fails silently: the code runs fine while predictions slowly get worse. The limits are that labels can arrive weeks late, so drift is only an early warning, and drift does not always hurt quality. Alerts need sensible thresholds and an owner, or people ignore them."
