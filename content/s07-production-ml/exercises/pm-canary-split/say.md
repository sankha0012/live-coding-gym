I hash the salt plus the user id with sha256 and take the integer modulo 100 to get a bucket. The user is in the canary if the bucket is below the percent, so the assignment depends only on the id and is the same on every server and every day. I avoid hash() because Python randomises it per process, and random because it would flip users between requests. Raising the percent only adds buckets, so nobody leaves the canary mid-rollout, and changing the salt gives a fresh split for the next experiment. It is O(1) per user. The trade-off is that the share is approximate for small samples.
