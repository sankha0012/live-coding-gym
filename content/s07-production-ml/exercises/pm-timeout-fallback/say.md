I read the injected clock before and after the model call and compare the elapsed time to the deadline. A normal result inside the deadline is returned with the path "model"; a slow result is discarded and the fallback is returned with "timeout"; an exception gives "error". Returning the path lets the caller count how often each case happens, which is the real monitoring signal. This version checks the time after the call, so it cannot interrupt a hung call; for that I would need a thread, an async timeout or a client-side timeout. I catch Exception, not BaseException, so Ctrl+C still works.
