I keep a checkpoint with the index of the next item and the results so far. I call the handler, and only after it returns do I append the result and move the index, so a crash leaves the failed item pending and finished items never run twice. On resume the same loop starts from the stored index. Cost is O(n) overall and O(1) extra per item. The weak spot is a crash between the handler's side effect and the checkpoint write: the item would run again, so the handler should be idempotent. In production the store is a file or table written atomically.
