The bug is that the dedupe keeps the last event for each id instead of the first. Assigning into a dict by key overwrites the earlier value, so the retried copy replaces the original. The number of duplicates is still right, so a quick check of the count looks fine, but the content is the later copy and the order follows first appearance of the id. The fix is to skip an id that has already been seen, using a set, and append the event only the first time. I would test with two events that share an id and have different fields, because only then does the choice of which copy survives show up.
