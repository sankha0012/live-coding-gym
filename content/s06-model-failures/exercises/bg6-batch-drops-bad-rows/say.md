The bug is that failed rows are dropped from the scores list. The `except` branch records the error but does not append `None`, so the scores list is shorter than the input and everything after a bad row moves one position left. The caller then joins scores back to rows by position and attaches the wrong score to the wrong row, with no error raised. The fix is one line: append `None` in the except branch so there is exactly one entry per input row. I would also assert that the scores list has the same length as the input, because that is the contract of a batch function.
