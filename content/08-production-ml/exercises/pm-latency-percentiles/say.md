I sort a copy of the data and for each percentile take the element at rank ceil(p * n / 100), minus one for zero-based indexing. I use integer ceiling division to avoid float rounding. The result is always an observed latency, which is what nearest rank means. It is O(n log n) because of the sort. Averages hide tail latency, so p95 and p99 are what I alert on. An empty window returns None, so the caller must handle that, and sorted() leaves the input list unchanged.
