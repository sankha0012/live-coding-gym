I wrap a deque so put and get are O(1). When the queue is full, the policy decides: drop_oldest evicts the front and keeps the fresh item, reject refuses the new one, and both increment a dropped counter. The counter matters because silent loss is dangerous, so I would export it as a metric and alert on it. For ML scoring, drop_oldest suits fresh-is-better data like live features; reject suits work that the caller can retry. The queue is not thread-safe, so with threads I would add a lock or use queue.Queue.
