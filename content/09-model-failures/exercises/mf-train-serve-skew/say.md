This is train and serve skew: the same feature is computed by two code paths that drifted apart. The serving code used log instead of log1p, did not treat a missing amount as 0.0, and did not clean the category. I spot it by running both paths on the same rows, including missing values and messy strings, and comparing. The smallest safe fix is to make serving call the training function on a one-row list, so there is one source of truth. The cost is small per row, and the trade-off is a little list overhead for a guarantee that the two cannot diverge.
