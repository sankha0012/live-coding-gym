I walk the list once and keep a score only if it is a real finite number. NaN is never equal to itself, so I use math.isfinite instead of an equality check. Bad values become the fallback and I count them, so the caller can alert when the count grows. It is O(n) time and space, and I build a new list so the input is not changed. A trade-off: a fixed fallback hides the failure from the model's users, which is why the count matters.
