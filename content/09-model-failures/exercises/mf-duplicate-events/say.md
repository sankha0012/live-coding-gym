I walk the events once and keep a set of ids I have seen. If the id is new I keep the event, otherwise I skip it, so the first event wins and the order is unchanged. The duplicate count is the input length minus the kept length. It is O(n) time and O(u) space for u unique ids. A trade-off is that keeping the first is a choice: if later events are corrections, you would want to keep the last one, and that is a different rule.
